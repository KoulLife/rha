## 2. 홈 / 대시보드 (역할별 구성)

2026-10-13 화면 결정과 `shadcn-ui-component-guide.md`를 기준으로 한다.

- 회원: 예약 완료·대기 신청·이용권 잔여·지난 수업/취소 요약, 공개 수업 최대 6개, 내가 예약한 수업 최대 2개, 내 이용권.
  - 예약 영역은 항상 2칸을 확보하며 부족한 칸은 공백으로 유지한다.
  - 이용권은 잔여 횟수·진행 바·오른쪽 범례·횟수 표·만료일·상태 순서다.
  - 읽지 않은 알림 수는 헤더와 메뉴에서 확인한다. 홈의 최근 알림과 빠른 메뉴는 표시하지 않는다.
- 강사: 오늘 담당 수업, 담당 수업의 예약·출결 현황, 종료된 수업의 출결 처리 대기, 내 부재 승인 대기, 본인 알림.
- 관리자: 오늘 전체 수업, 전체 예약·출결 현황, 강사 부재 승인 대기, 본인 알림.
- 공통 상태: 불러오는 중, 조회 실패와 재시도, 로그인 만료, 권한 없음, 데이터 없음.
- 대기 신청은 현행 API에 없는 제안 기능이다. 화면 예시를 실제 저장 기능으로 간주하지 않는다.

#### 3.1의 강사·관리자 대응 화면 — 첨부 회의안

- 와이어프레임 메뉴·버튼명: **승인 신청 대기**

회원이 수업을 신청한 뒤 강사·관리자가 처리할 화면도 같은 수업 흐름에 포함한다. 메뉴 번호가 회원용이라는 이유로 아래 업무를 와이어프레임에서 제외하지 않는다.

| 역할 | 수업 흐름의 화면·행동 |
| --- | --- |
| 강사 | 담당 수업 목록·상세 → 예약 신청 목록·회원 상세 → 예약 확정·거절 → 확정 예약 취소 → 대기자 목록·순서 → 대기 회원 예약 확정·대기 취소 → 출석·노쇼·정정·수업 종료 |
| 관리자 | 전체 수업과 위 신청·예약·대기·출결 처리 → 수업 개설·수정·공개·공개 예약·취소 |

- 강사의 수업 개설·수정·공개·취소는 해당 유형의 운영 권한이 있어야 한다.
- 위 예약 승인·대기 처리와 출결 시 차감은 **회의안 화면 제안**이며 현행 API 계약에는 없는 부분이 있다. 기존 회원 화면의 즉시 예약 방식과 차이가 있어 운영 정책·계약 합의가 필요하다.
- 근거·화면별 API·누락 사항은 `docs/wireframes/wireframe-api-mapping.md`의 회의안 절에 기록한다.

## 7. 회원 이용권

회원별 이용권을 조회하고 발급·변경·홀딩·결제까지 처리하는 업무 메뉴다. 
전체 회원을 대상으로 조회할 수 있으며, 특정 회원의 이용권은 `회원 관리 > 회원 상세 > 이용권`에서도 동일한 화면으로 진입한다.

- 관리자: 발급·조정·홀딩·결제 관리.
- 회원: 기존 `내 이용권`에서 본인 이용권과 처리 결과 조회.
- 강사: 담당 수업 예약 상세의 이용권 요약 조회. 전체 이용권 관리 메뉴는 제공하지 않는다.
- 와이어프레임·역할별 API 정리: `docs/wireframes/07-pass-management-{admin,member,instructor}-api.md`.

### 7.1 이용권 현황

## 12. 흐름과 데이터 모델의 추가 확인 항목
