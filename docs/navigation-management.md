# 역할별 메뉴 관리

## 기존 구조와 결정

기존에는 `frontend/src/config/access.ts`의 회원/운영진 메뉴 배열을 App에서 합쳐 역할과 권한으로 필터링했다. 상세 화면의 상위 메뉴 관계는 화면 이동과 사이드바 선택 표시에 각각 있었고, 화면 이름은 `app/routes.ts`에 별도로 정의되어 있었다.

메뉴 정의와 상세 화면 관계를 `config/access.ts`로 통합한다. 메뉴 표시, 화면 이동 검사, 사이드바 선택 표시, 현재 위치 이름이 같은 설정을 사용한다. Screen 타입도 설정에서 유도하므로 별도의 화면 ID 목록을 수정할 필요가 없다. 화면 렌더링과 업무별 데이터 필터링은 기존 컴포넌트에 유지한다.

## 수정 방법

- 메뉴 순서: `menuItems` 배열 순서. 역할 필터링 후에도 순서를 유지한다.
- 노출 역할/필요 권한: `roles`, `permission`. 두 조건 모두 만족해야 한다.
- 메뉴 이름: `label`. 역할별 차이는 `roleLabels`로 지정한다.
- 현재 위치 이름: 기본적으로 메뉴 이름을 사용한다. 별도 이름이 필요하면 `pageLabel`을 지정한다.
- 상세 화면: `detailScreens`에 이름과 상위 메뉴를 등록한다. 상위 메뉴의 접근 조건과 선택 표시를 공유한다.
- 신규 화면 구현: 설정 등록 외에 App의 화면 렌더링 연결과 해당 컴포넌트 구현이 필요하다.

관리자 강사 관리·수업 운영·회원 이용권·스튜디오 설정은 `config/access.ts`의 `submenus`를 사용한다. 정산 내역과 수당 기준은 강사 관리의 하위 메뉴다. 각 항목의 `activeScreens`에 상세 화면을 포함해 선택 표시를 유지한다. 하위 메뉴는 상위 메뉴의 역할·권한 조건을 공유한다. 부모 버튼은 펼침만 변경하며 한 번에 한 그룹을 펼친다. 하위 메뉴를 선택하거나 상세 화면으로 진입하면 소속 그룹이 자동으로 펼쳐지고, 모바일은 이동 후 사이드바를 닫는다. 회원 관리처럼 독립적인 화면은 메뉴로 유지하며, 공통 알림 화면은 상단 헤더 알림 버튼으로 진입한다.

수업 운영의 예약·출결은 별도 하위 메뉴가 아닌 수업 상세의 예약자 목록에서 처리한다. 관리자 홈의 수업별 `예약자 보기`도 해당 수업 상세로 이동한다.

기존 운영 설정과 내 메뉴 안내를 하단의 **스튜디오 설정**으로 통합했다. 하위 메뉴는 운영 기본 설정, 이용권 상품, 수업 유형, 룸이다. 운영 기본 설정에서 예약 정책과 요일별 영업시간·정기 휴무를 바로 편집한다. 상품·유형·룸의 현재 등록 항목도 조회하고 관리 화면으로 이동한다. 사용자 요청에 따라 기존 API만 사용하며 연락처·로고·구독 등 별도 계약이 필요한 설정은 추가하지 않는다.


## 권한의 범위

현재 모든 역할은 `mocks/member.ts`의 동일한 예시 권한 목록을 사용하며, 역할 필터로 메뉴를 구분한다. 이번 정리에서는 기존 권한 정책을 유지했다. 부재 승인 대기 조회의 `profile.read` 매핑도 기존 예시 정책이다.

실제 인증 연동 시 서버가 제공하는 사용자 권한을 전달하도록 교체해야 한다. 프론트 메뉴 숨김과 이동 검사는 사용성 제어이며 서버의 API 권한 검사를 대체하지 않는다. 버튼의 실행 권한과 사용자별 데이터 범위는 메뉴 표시 조건과 별도로 관리한다.
