# R.HA 프론트엔드

React + TypeScript + Vite + Tailwind CSS 4, shadcn/ui의 Radix 기반 `radix-nova` 스타일을 사용한다.

## 실행

```bash
cd frontend
npm install
npm run dev
```

## 공통 UI

- 화면 구성: `../docs/wireframes/wireframes.html`
- 컴포넌트 사용 규칙: `../docs/shadcn-ui-component-guide.md`
- 업무 메뉴: `../docs/menu-structure.md`
- 역할별 메뉴 설정: `src/config/access.ts`. 메뉴 순서·노출 역할·권한·역할별 이름·상세 화면 관계를 관리한다. 관리 방법과 예시 권한의 범위는 `../docs/navigation-management.md` 참고.
- shadcn 설정: `components.json`. 부품은 `@/components/ui/*`에서 가져온다.
- 부품 추가: `npx shadcn@latest add <컴포넌트명>`. 공통 부품과 설정은 Git으로 공유하며 기존 부품을 덮어쓰기 전에 변경 내용을 확인한다.
- 전역 토큰·기본 스타일: `src/globals.css`. 색상·간격·radius·글꼴 크기의 공통 값은 여기에서 조절한다. 본문 15px, 보조 설명 13px, 기본 컨트롤 높이 44px·작은 버튼 40px, 카드 그림자 없음.
- 화면 전용 스타일: 인증은 `src/features/auth/auth.css`, 회원 메뉴는 `src/features/member/member.css`, 회원 홈은 `src/features/dashboard/member-home.css`, 강사·관리자 대시보드는 `src/features/dashboard/dashboard.css`, 홈 로딩·오류 상태는 `src/features/dashboard/dashboard-state.css`에서 관리한다. 각 스타일 파일은 해당 화면 컴포넌트가 가져온다.
- 공통 부품 스타일: 로고·버튼·상태 배지·표·대화상자는 해당 컴포넌트 옆 CSS에서 관리한다. 반복되는 표현은 컴포넌트 variant로 추가하고, 색상·간격·radius 값은 전역 토큰을 사용한다.
- 앱 셸은 `src/app/shell.css`, 이전 화면에서 쓰는 규칙은 `src/app/legacy.css`에 둔다. `src/main.tsx`는 전역 토큰을 먼저 불러와 스타일 레이어 순서를 고정한다.
- 홈·대시보드는 다른 팀원의 작업 범위로, 기존 배치·높이·간격·전용 스타일을 유지한다. 공통 스타일 변경은 공유하지만 화면 전용 덮어쓰기는 추가하지 않는다.
- 홈 외 화면(인증, 수업·이용권·예약·계정·알림, 강사·관리자 조회 화면)에 새 스타일을 적용한다. 업무 화면의 제목은 24px, 이용권 잔여 숫자는 30px/굵기 300, 카드 여백은 데스크톱 20px·모바일 16px이다. 운영진 조회 화면은 `.dashboard-subpage`로 한정한다.
- 기존 회원 화면 스타일은 `src/app/legacy.css`의 `legacy` 레이어 안 `.member-preview` 범위에 둔다.

## 인증 화면과 미리보기

첫 화면은 로그인이다. 인증 화면은 React Hook Form과 shadcn의 Card, Field, Input, Button, Alert를 사용한다. 계정 메뉴는 DropdownMenu, 로그아웃 확인은 AlertDialog, 결과 알림은 Sonner를 사용한다. 장식 아이콘은 표시하지 않는다.

메뉴 1의 로그인, 이메일 인증, 회원가입, 비밀번호 재설정 요청/새 비밀번호 설정, 로그아웃 흐름을 메모리 예시 데이터로 제공한다. API와 실제 이메일 발송은 연결하지 않았으며 입력값과 계정은 새로고침하면 초기화된다. 인증 관련 네트워크 요청과 브라우저 저장소 사용은 없다. 실제 API 연동 시 OpenAPI로 생성한 훅을 사용해야 한다.

- 예시 계정: `demo@rha.example` / `RhaDemo123!`.
- 이메일 인증: 새 이메일로 코드를 요청하면 화면 아래에 미리보기 코드가 표시된다. 재요청하면 이전 코드는 무효화된다.
- 회원가입: 인증된 이메일, 이름, 생년월일, 휴대전화, 8~64자 비밀번호가 필수다. 주소는 선택이며 역할은 항상 MEMBER다.
- 비밀번호 재설정: 가입 여부와 관계없이 같은 접수 안내를 표시한다. `재설정 메일 링크 미리보기`로 새 비밀번호 화면을 확인한다. 등록된 예시 계정에만 변경을 적용한다.
- 로그아웃: 계정 메뉴 또는 상단 버튼에서 확인 후 로그인 화면으로 돌아간다. 취소하면 기존 화면을 유지한다.
- 예시 코드 유효 시간 5분, 가입 인증 토큰과 재설정 링크 유효 시간 30분은 **미리보기용 값**이며 실제 서버 정책은 별도다.
- 로그인 결과의 역할에 따라 회원·강사·관리자 홈을 표시한다. 회원가입은 항상 MEMBER이며, 비밀번호 재설정은 기존 역할을 유지한다. 로그인 아래의 역할별 미리보기 버튼으로 각 홈을 바로 확인할 수 있다.

## 역할별 홈과 내비게이션

메뉴 구조도 2번과 UI 가이드에 따라 회원·강사·관리자 홈을 공통 셸과 Card/StatusBadge로 구성한다.

- 회원: 공개 수업 최대 6개, 내가 예약한 수업 최대 2개(항상 2칸), 내 이용권과 예약·대기·잔여·지난 기록 요약. 알림 수는 헤더와 메뉴에서 확인하며 홈에 최근 알림·빠른 메뉴는 두지 않는다.
- 강사: 오늘 담당 수업, 담당 수업의 예약·출결, 종료된 수업의 출결 처리 대기, 내 부재 승인 대기, 내 알림.
- 관리자: 오늘 전체 수업, 전체 예약·출결, 강사 부재 승인 대기, 내 알림.
- 요약 지표와 전체 보기에서 해당 조회 화면으로 이동한다. 수업별 예약자·출결은 Table, 회원 수업은 Card 목록이다. 알림은 중앙 Radix Dialog에서 조회하고 메모리에서 읽음으로 표시하며 헤더·메뉴·홈의 미읽음 수를 함께 갱신한다.
- 신규 가입 계정은 기존 예시 회원의 수업·이용권·알림을 홈에 표시하지 않는다.

`src/features/dashboard/preview.ts`는 2026-10-13 12:00 서울 시각의 고정 예시 데이터이며 화면에도 예시 기준을 표시한다. `model.ts`에서 서울 날짜 경계, 역할과 사용자 ID, 예약·출결 상태로 필터링·집계한다. 실제 API/MSW 연동과 출결 저장·부재 승인/반려는 연결하지 않았다. 별도 대시보드 API를 추가하지 않았으며 이후 `wireframe-api-mapping.md`에 정의된 기존 API의 생성 훅으로 교체한다.

예시 계정의 비밀번호는 모두 `RhaDemo123!`이다.

| 역할 | 이메일 |
|---|---|
| 회원 | `demo@rha.example` |
| 강사 | `instructor@rha.example` |
| 관리자 | `admin@rha.example` |

공통 내비게이션은 shadcn의 SidebarProvider, Sidebar, SidebarMenuButton을 사용한다. 프로젝트 공통 `brand` variant는 연한 그린 배경과 굵은 텍스트로 선택 상태를 표시하고 장식 아이콘이나 왼쪽 강조선을 사용하지 않는다. 모바일은 Sidebar가 제공하는 열림 상태와 텍스트 메뉴 열기/닫기 버튼을 사용한다. Sheet는 Sidebar의 내부 의존성이며 업무 상세/폼에는 사용하지 않는다.

## 메뉴 1·2 UI 검토 범위

- 와이어프레임의 화면 구조를 `docs/shadcn-ui-component-guide.md`의 shadcn 컴포넌트·variant·토큰으로 구현한다.
- 로그인 아래 `홈 화면 상태 선택`을 펼쳐 정상/불러오는 중/데이터 없음/조회 실패/로그인 만료/권한 없음을 선택하고 역할별 미리보기를 연다.
- 로딩은 화면 검토를 위해 유지된다. 계정 메뉴의 로그아웃으로 돌아갈 수 있다. 조회 실패의 `다시 시도`는 정상 예시로 전환하고, 만료/권한 없음의 로그인 복귀는 로그인 화면을 연다.
- 인증은 기존 로컬 예시의 입력 검증·제출 중·실패·성공 화면으로 검토한다. 실제 메일·세션·네트워크 동작을 의미하지 않는다.
- 사용자가 확정한 회원 홈 6개/2칸 배치, 로고, 오른쪽 범례, 강조된 표 제목 행을 유지한다. 로그인 로고는 원본이고 사이드바는 별도 문구를 사용한다.
- 완료 범위는 UI 디자인과 예시 화면 전환이다. API 생성 훅·MSW·백엔드·실제 이메일 발송은 이번 작업 범위에 포함하지 않는다.

## 관리자 업무 화면 (2026-10-13)

로그인 화면의 **관리자 화면 열기**, 또는 `admin@rha.example` / `RhaDemo123!`로 확인한다.

- 회원 관리: 이름·이메일 검색, 상태·페이지, 기본 정보·상태 변경, 상세의 이용권·예약·출결·결제.
- 강사 관리: 등록·정보·상태·권한 전체 교체·가능시간, 부재 목록·상세·승인·반려·취소·영향 수업 연결, 퇴사일·수업 인계·퇴사 처리·퇴사자 정산 연결.
- 수업 운영: 회차 필터·목록·상세, 개설·수정·공개/비공개·공개 예약·취소, 예약 목록·상세·취소·출석·노쇼·출결 정정.
- 회원 이용권: 전체/회원별 조회, 새 발급·재등록, 잔여·만료일·강사 조정, 홀딩 등록·예정·해제, 결제 기록·수정·삭제·환불 여부 기록.
- 스튜디오 설정: 운영 기본 설정에서 예약 정책·영업시간을 바로 편집하고 상품·유형·룸 현황을 확인한다. 상품 등록·수정·발급분 영향 확인·삭제, 수업 유형 등록·수정·활성 상태, 룸 등록·수정·사용 수업 확인·삭제, 요일별 영업시간·예약 정책.
- 강사 수당·정산: 유형별 단가, 기간 계산, 수업별 항목, 검토·확정·지급 사실 기록·미확정 정산 폐기, 처리 이력.
- 관리자 본인 알림·미읽음 수·개별/전체 읽음, 활동 이력 필터·변경 전후·관련 화면.

기존 `MenuPanel`, `Table`, `StatusBadge`, `Tabs`, 중앙 Dialog/AlertDialog와 전역 토큰을 사용한다. 기존 회원·강사 홈 배치를 유지하고 관리자 홈 데이터만 관리자 조회 결과에 연결한다.
